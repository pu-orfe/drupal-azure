# Exported configuration

`drush config:export` writes here, and `docker-entrypoint.sh` runs
`drush config:import` from here on the first boot of every new image.

That makes this directory the authority for the site's configuration: it ships
inside the image, so it is immutable per deploy and versioned with the code that
expects it. A configuration change is therefore a commit and a deploy, not a
click in the admin UI — and a rollback undoes it, because the older image carries
the older `config/sync` and re-imports it.

Two consequences worth knowing:

- **Changes made in the admin UI are transient.** The next deploy's
  `config:import` reverts anything not exported here. Export and commit, or lose
  it.
- **An empty directory is not an error.** The entrypoint skips `config:import`
  when there are no `*.yml` files, so a fresh template deploys cleanly. Run
  `drush config:export` after the first install and commit the result.

`.htaccess` is generated by Drupal to keep the directory unreadable over HTTP.
Leave it.
